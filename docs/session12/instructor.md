### 説明どころ

- 断片の作りでは、ページと断片が同じ `_task_list.html` を使う。表示の決まりはテンプレート1か所で、テストは pytest で HTML を確かめられる。JSON 版は状態の文字と class を `done-json.js` でもう一度書いている（二重管理）
- `app.js` がエラーの断片を `innerHTML` で入れているのは、サーバの Jinja2 がエスケープ済みの HTML だから。利用者の入力をそのまま `innerHTML` に入れる（第3回の XSS）のとは違う
- `action` を残して `data-fragment` を足すので、JavaScript がなくても第11回と同じに動く。第11回のテスト53件は1件も書き換えていない
- 素朴な版で完了がふつうの送信になるのは、追加の応答で `#task-list` を丸ごと差し替え、イベントを付けたフォームが DOM から消えたから。追加のフォームは差し替えないので、追加はずっと `fetch` のまま
- BUG-001 は部分更新で生まれた不具合。ページ全体を返す版は完了で `/` に移って絞り込みもリセットされたが、部分更新ではページの URL とリンクが残るので、表示中の状態を自分で断片の要求に載せる必要がある。断片のテストを「すべて」の表示でしか書いていなかったことが見逃しの理由

### 講師が見せる補足（任意）

時間が余ったとき、または質問が出たときに講師の画面で見せます。受講者の課題にはしません。

- ポーリング: 次の数行で、ほかのタブの変更が5秒ごとに反映される。Network で、変化がなくても断片を取りに行き続けることを見せる

    ```js
    setInterval(async () => {
      const response = await fetch("/fragments/tasks" + location.search);
      document.getElementById("task-list").outerHTML = await response.text();
    }, 5000);
    ```

- SSE（`EventSource`）と WebSocket: サーバは `/events` で「変わった」とだけ送り（`StreamingResponse`、`media_type="text/event-stream"`）、ブラウザは `message` を受けたら `GET /fragments/tasks` を取り直す。双方向に送るなら WebSocket。どちらも Network の1行が開きっぱなしになる
- htmx: フォームに `hx-post="/fragments/tasks/3/done" hx-target="#task-list" hx-swap="outerHTML"` を付けると app.js が要らない。今日の作り（サーバが断片、ブラウザは差し替えるだけ）をライブラリにしたもの。htmx は既定では 4xx を差し替えないので、エラーの断片を出すには設定が要る。本体は `static/vendor/` に置く（CDN を使わない）
