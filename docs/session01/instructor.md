### 演習用ログに仕込んであること

ログは `tools/scripts/generate_session01_logs.py` が作ります。次の傾向を意図的に入れてあります。

| 仕込み | 狙い |
| --- | --- |
| INFO 行に `GET /help/error-codes` がある | `grep -i error` だと ERROR 以外の行も数えてしまう（問3） |

## つまずきやすい点

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `cd ~/handsoff/...` で `No such file or directory` | 研修ディレクトリを Windows 側（`/mnt/c/...`）に置いた | `ls ~` で場所を確かめ、Linux 側に置き直す |
| `cp` で `No such file or directory` | `workspace/session01` 以外の場所で実行した | `pwd` で今いる場所を確かめる。相対パスは「今いる場所から」と説明する |
| `less` や `man` から抜けられない | 終了キーを知らない | `q` で終わる |
| `grep -c ERROR logs/*.log` の結果が1つの数にならない | 複数ファイルを渡すと `-c` はファイルごとの件数を出す | `cat logs/*.log \| grep -c ERROR` か `grep -h ERROR logs/*.log \| wc -l` にする |
| `cut -c12-13` の結果が時刻にならない | `grep` に複数ファイルを渡すと、行頭にファイル名が付く | `grep -h` でファイル名を付けない |
| `chmod u-r` の後でも `cat` できてしまう | root で作業している（root は権限を無視する） | `whoami` で確かめる。一般ユーザーで作業するよう伝える |
| Windows のメモ帳で作業ログを書いたら、Linux 側で文字化けする・改行が `^M` になる | 文字コードや改行コード（CRLF）の違い | VS Code（WSL 拡張）で開くよう案内する。詳しくは第2回以降で扱う |

## 解答例

### 演習

研修ディレクトリの `workspace/session01/` で実行した結果です。

| 問 | 答え | コマンドの例 |
| --- | --- | --- |
| 1 | 51 行 | `grep -c ERROR logs/todo-app-2026-04-03.log` |
| 2 | 124 行 | `cat logs/*.log \| grep ERROR \| wc -l` |
| 3 | 201 行（77 行多い） | `cat logs/*.log \| grep -i error \| wc -l` |
| 4 | 71 行（文字列だけで数えると 97 行） | `cat logs/*.log \| grep ERROR \| grep -c 'database is locked'` |

- 問3の理由: `-i` は大文字と小文字を区別しない。`GET /help/error-codes` を含む INFO 行も数えてしまう
- 問4の理由: `database is locked, retrying (1/3)` という WARN 行も含んでしまう。WARN はリトライで回復した記録なので、失敗の件数には入れない
- 問3・問4で伝えたいこと: 「何を数えたいか」を先に決めてから、条件を書く。第9回の受け入れ条件（確かめられる形で書く）と同じ考え方

### 講師が見せる集計（任意）

時間が余ったときに、手順5の続きとして講師の画面で見せます。受講者の課題にはしません。


```sh
# 1. find で探す（old/ の下のファイルも見つかる。全部で 8 ファイル）
find ~/handsoff/docs/session01/assets/logs -name '*.log'

# 2. find + xargs で ERROR の合計（old/ の分を含めて 145 行）
find ~/handsoff/docs/session01/assets/logs -name '*.log' | xargs grep -h ERROR | wc -l

# 3. database is locked（ERROR）の日ごとの件数
grep -h 'ERROR.*database is locked' logs/*.log | cut -d' ' -f1 | sort | uniq -c
#   8 2026-04-01
#   4 2026-04-02
#  40 2026-04-03   ← 目立つ
#   1 2026-04-05
#  13 2026-04-06
#   5 2026-04-07

# 04-03 の ERROR を時間帯ごとに集計すると 12 時台が 26 件
grep -h ERROR logs/todo-app-2026-04-03.log | cut -c12-13 | sort | uniq -c

# 12 時台のログを見ると backup started / backup finished に挟まれている
grep ' 12:' logs/todo-app-2026-04-03.log | grep -v ERROR

# 4. 部品ごとの ERROR 件数
grep -h ERROR logs/*.log | cut -d' ' -f4 | sort | uniq -c | sort -rn
#   71 [db]
#   29 [web]
#   24 [mail]
```

- 3で期待する仮説: 「12時台のバックアップ処理とタスクの書き込みが重なり、DB がロックされた」。原因を言い切らず、仮説と根拠（時刻が一致する行）を分けて話す
- 04-04 には `database is locked` の ERROR がない。土日はログ自体が少ないので、日ごとの件数を比べるときは母数が違うことにも触れる
