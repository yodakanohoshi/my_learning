# BUG-001 期限切れだけを表示中に完了すると、全部のタスクが表示される

Issue: #19（ラベル: `不具合`）に同じ内容で起票した。リポジトリにも控えを残す。

## 概要

「期限切れだけ」の表示中に「完了」を押すと、一覧が期限切れ以外のタスクも含む全件の表示に変わる。絞り込みのリンクは「期限切れだけ」が選ばれたまま。

## 再現手順

1. `mise run db-reset` で開発用 DB を消し、`mise run dev` で起動する
2. <http://127.0.0.1:8000> で、次の3件を追加する
    - 「牛乳を買う」期限 昨日
    - 「本を返す」期限 昨日
    - 「レポートを出す」期限 来週
3. 「期限切れだけ」を押す（「牛乳を買う」「本を返す」の2件が出る）
4. 「牛乳を買う」の「完了」を押す

## 期待結果

一覧は「期限切れだけ」のまま。「本を返す」の1件だけが出る。

根拠: ストーリー S-04 の受け入れ条件 (15)「一覧ページの『期限切れだけ』のリンクで、期限切れのタスクだけが出る」。API設計書 2章 A-01「『期限切れだけ』の表示中は、`data-fragment` の URL にも `?overdue=1` を付ける」。表示を切り替える操作をしていないので、絞り込みは続くはず。

## 実際の結果

一覧が全件の表示になり、完了にした「牛乳を買う」と、期限切れでない「レポートを出す」も出る。ページを再読み込みすると「本を返す」の1件だけに戻る。

## 環境

- コミット: `main`（第12回の PR #18 で fetch による部分更新を入れた後）
- ブラウザ／OS: Chrome（Windows 11）。サーバが返す断片の問題なのでブラウザには依存しない
- 開発者ツールの Network タブ: `POST /fragments/tasks/1/done` に `?overdue=1` が付いていない

## 重要度

低: 再読み込みすれば正しく出る。ただし、完了したつもりのものが一覧に残って見えるので紛らわしい。

## 補足

- 原因: 完了ボタンの `data-fragment` が常に `/fragments/tasks/{id}/done` で、表示中の絞り込みを断片の URL に渡していなかった。断片の URL（A-04〜A-06）は `overdue` を受け取れるが、送られてこなかった
- 修正: 表示中の絞り込みを断片の URL のクエリ（`?overdue=1`）で渡す。`web.py` の `overdue_query` でクエリを作り、テンプレート（`index.html`・`_task_list.html`）の `data-fragment` の末尾に `{{ query }}` で付ける
- テスト: `tests/test_web.py` の `test_BUG001_期限切れだけの表示中に完了しても期限切れだけを返す`（修正の前に書いて、失敗することを確かめた）
- なぜ見逃したか: ページ全体を返す版では、完了すると `/` へ移って「すべて」の表示に戻る（絞り込みのリンクも「すべて」になるので食い違わない）。部分更新では一覧だけを差し替え、ページの URL と絞り込みのリンクは残るので、表示中の状態を断片の要求に自分で載せる必要があった。断片のテストを「すべて」の表示でしか書いていなかった
- 再発防止: 断片を返す URL を足すときは、画面の状態（絞り込みなど）を引き継ぐテストも書く
