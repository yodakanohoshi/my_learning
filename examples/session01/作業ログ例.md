## 1. 全体: カーネルとユーザー空間

```console
$ uname -a
Linux DESKTOP-XXXX 6.6.87.2-microsoft-standard-WSL2 #1 SMP PREEMPT_DYNAMIC ... x86_64 GNU/Linux
$ grep PRETTY /etc/os-release
PRETTY_NAME="Ubuntu 24.04.3 LTS"
$ ls /mnt/c/Users
'All Users'   Default  'Default User'   Public   desktop.ini   trainee
```

- カーネルの名前に `microsoft-standard-WSL2` とあった。Windows の上で Linux のカーネルが動いている
- Windows の `C:\Users` が Linux からは `/mnt/c/Users` として見える
- `explorer.exe .` でホームディレクトリをエクスプローラーで開けた。アドレス欄は `\\wsl.localhost\Ubuntu\home\trainee` だった

## 2. プロセス

```console
$ echo $$
1234
$ ps -p 1 -o pid,comm
    PID COMMAND
      1 systemd
$ sleep 300 &
[1] 1301
$ ps -f
UID          PID    PPID  C STIME TTY          TIME CMD
trainee     1234    1233  0 13:20 pts/0    00:00:00 -bash
trainee     1301    1234  0 13:25 pts/0    00:00:00 sleep 300
trainee     1302    1234  0 13:25 pts/0    00:00:00 ps -f
$ kill %1
[1]+  Terminated              sleep 300
```

- 自分のシェル（bash）の PID は 1234。`sleep` と `ps` の PPID も 1234 なので、どちらもシェルの子プロセス
- PID 1 は `systemd`。`pstree -p` でたどると `systemd(1)` → … → `bash(1234)` → `pstree` とつながっていた
- `kill` はシグナル（SIGTERM）を送るコマンドで、`Terminated` と表示された

## 3. ファイルシステム

```console
$ ls -l /proc/$$/fd
lrwx------ 1 trainee trainee 64 Oct XX 13:30 0 -> /dev/pts/0
lrwx------ 1 trainee trainee 64 Oct XX 13:30 1 -> /dev/pts/0
lrwx------ 1 trainee trainee 64 Oct XX 13:30 2 -> /dev/pts/0
$ ls /nothing 2> err.txt
$ cat err.txt
ls: cannot access '/nothing': No such file or directory
```

- 0・1・2 はどれも端末（`/dev/pts/0`）につながっている。`2>` でエラーだけをファイルに分けられた
- `/proc` の下は実際のファイルではなく、カーネルがプロセスの情報を見せている

### リダイレクトで残す

```console
$ echo "## 2026-04-03 のエラー" > memo.md
$ grep -c ERROR logs/todo-app-2026-04-03.log >> memo.md
$ cat memo.md
## 2026-04-03 のエラー
51
```

- 2行目を `>` にして試したら、見出しが消えて件数だけになった。`>` は上書き、`>>` は追記

### 権限を読む・変える

```console
$ ls -l memo.md
-rw-r--r-- 1 trainee trainee 30 Oct XX 13:33 memo.md
$ chmod u-r memo.md
$ ls -l memo.md
--w-r--r-- 1 trainee trainee 30 Oct XX 13:33 memo.md
$ cat memo.md
cat: memo.md: Permission denied
$ chmod 644 memo.md
```

- 自分（所有者）の `r` が消えると、自分のファイルでも読めなくなった
- `644` は 所有者=6（r+w）、グループ=4（r）、その他=4（r）

## 4. ネットワーク

```console
$ ip -br addr
lo               UNKNOWN        127.0.0.1/8 ::1/128
eth0             UP             172.24.80.15/20 fe80::215:5dff:fe12:3456/64
$ ip route
default via 172.24.80.1 dev eth0 proto kernel
172.24.80.0/20 dev eth0 proto kernel scope link src 172.24.80.15
$ python3 -m http.server 8000 &
$ ss -tln | grep 8000
LISTEN 0      5            0.0.0.0:8000      0.0.0.0:*
$ curl -v http://127.0.0.1:8000/ | head -n 3
*   Trying 127.0.0.1:8000...
* Connected to 127.0.0.1 (127.0.0.1) port 8000
> GET / HTTP/1.1
...
< HTTP/1.0 200 OK
$ kill %1
```

- 自分の IP アドレスは `172.24.80.15`。外への出口（default）は `172.24.80.1`
- `ss` で 8000 番ポートの待ち受け（トランスポート層）を見てから、`curl -v` で HTTP のやり取り（アプリケーション層）を見た。`>` が送ったもの、`<` が受け取ったもの
