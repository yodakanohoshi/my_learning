# ユーザーストーリー TODO アプリ（Web 版）

| 項目 | 内容 |
| --- | --- |
| 版 | 1.0（第9回） |
| 関連 | [要件メモ](requirements.md) |

ストーリーは GitHub の Issue に1件ずつ登録する（タイトル: `S-01 タスクを追加する` の形、ラベル: `ストーリー`、マイルストーン: `Web 版`）。ここには Issue の本文と同じ形で控えを残す。受け入れ条件がすべて満たされ、テスト付きでマージされたら Issue を閉じる（PR に `Closes #番号` を書く）。

- 受け入れ条件の番号 (1)〜(15) は全ストーリーの通し番号。第11回のテスト名の頭にも同じ番号を付ける（`test_9_期限の当日はまだ期限切れではない`）
- 見積はタスクに分けて幅で書き、根拠を一言添える

## 一覧

| ID | ストーリー | 優先度 | 見積 | Issue |
| --- | --- | --- | --- | --- |
| S-01 | タスクを追加する | 必須 | 3〜5時間 | `#8` |
| S-02 | タスクの一覧を見る | 必須 | 2〜4時間 | `#9` |

| S-04 | 期限切れのタスクだけを見る | あると良い | 1〜2時間 | `#11` |

## S-01 タスクを追加する

### ストーリー

利用者として、ブラウザでタイトルと期限を入れてタスクを追加したい。なぜなら、思いついたときにターミナルを開かずに書き留めたいから。

### 受け入れ条件

- [ ] (1) 一覧ページの上のフォームでタイトル「牛乳を買う」と期限 2026-11-01 を入れて追加すると、一覧ページに戻り「未着手」で出る（期限は空でもよい）
- [ ] (2) タイトルの前後の空白は除いて保存する
- [ ] (3) タイトルが空（空白だけを含む）なら追加せず、「タイトルを入力してください」と出る
- [ ] (4) タイトルが101文字以上なら追加せず、「タイトルは100文字以内で入力してください」と出る（100文字ちょうどは追加できる）
- [ ] (5) 期限が日付の形でなければ追加せず、「期限は YYYY-MM-DD の形で入力してください」と出る
- [ ] (6) (3)〜(5) のとき、入力した値はフォームに残る

### 見積

| タスク | 見積 | 根拠 |
| --- | --- | --- |
| FastAPI と Jinja2 の土台（起動・一覧ページの枠） | 1〜2時間 | 初めて使うので幅を広めに取った |
| SQLite の保存先（`SqliteStore`） | 1〜2時間 | `JsonStore` と同じ約束なので、テストは使い回せる |
| 追加フォームと入力チェック | 1時間 | チェックは CLI の `validate_title`・`parse_due` を使う |
| 合計 | 3〜5時間 | |

### 関連

- [要件メモ](requirements.md)、API設計書・DB設計書（第10回に書く）

## S-02 タスクの一覧を見る

### ストーリー

利用者として、タスクの一覧を期限が近い順に見たい。なぜなら、次に何をやればよいかを一目で知りたいから。

### 受け入れ条件

- [ ] (7) `/` を開くと、全タスクが期限が近い順に並ぶ。期限なしは最後、期限が同じなら番号の順
- [ ] (8) 各タスクに、タイトル・期限（`YYYY-MM-DD`）・状態（未着手・完了・期限切れ）が文字で出る
- [ ] (9) 期限の当日のタスクは「未着手」、翌日以降も完了していなければ「期限切れ」と出る
- [ ] (10) タイトルに `<script>` などの記号があっても、HTML として解釈されずに文字のまま出る
- [ ] (11) タスクが1件もなければ「タスクはありません」と出る

### 見積

| タスク | 見積 | 根拠 |
| --- | --- | --- |
| 一覧のテンプレート（期限・状態・空のとき） | 1〜2時間 | HTML を書くのが初めて |
| 並べ替えと状態の表示 | 1〜2時間 | CLI の `sort_by_due`・`Task.status` を使う |
| 合計 | 2〜4時間 | |

### 関連

- [要件メモ](requirements.md) 1章 状態遷移図

## S-03 タスクを完了にする

### ストーリー

利用者として、終えたタスクをボタン1つで完了にしたい。なぜなら、残っているものだけに集中したいから。

### 受け入れ条件

- [ ] (12) 未着手・期限切れのタスクに「完了」ボタンが出る。完了したタスクには出ない
- [ ] (13) 押すと一覧ページに戻り、そのタスクが「完了」になる。期限切れだったものも「完了」になる
- [ ] (14) ないタスクを完了にしようとしたら、404 で「タスクが見つかりません」と出る

### 見積

| タスク | 見積 | 根拠 |
| --- | --- | --- |
| 完了ボタンと完了の処理 | 1〜2時間 | S-01 と同じ形のフォーム。`SqliteStore.mark_done` は S-01 で作る |

### 関連

- [要件メモ](requirements.md) 1章 状態遷移図

## S-04 期限切れのタスクだけを見る

### ストーリー

利用者として、期限切れのタスクだけを表示したい。なぜなら、朝に遅れているものから片付けたいから。

### 受け入れ条件

- [ ] (15) 一覧ページの「期限切れだけ」のリンクで、期限切れのタスクだけが出る（`/?overdue=1`）。「すべて」のリンクで全タスクの表示に戻る

### 見積

| タスク | 見積 | 根拠 |
| --- | --- | --- |
| 絞り込みのリンクと表示の切り替え | 1〜2時間 | 判定は `Task.status` を使う。表示の切り替えだけ |
