# 環境設定手順書（WSL・Ubuntu）

WSL の Ubuntu で、自分のコマンドの置き場所を PATH に足し、apt でパッケージを入れ、社内ネットワークから curl・apt・git でインターネットにつなげるようにする手順です。

- 対象: 社内ネットワークにつないだ Windows PC の WSL（Ubuntu 26.04）。社外のネットワークでは手順3を飛ばす
- 所要時間: 20〜30分
- 必要なもの: `sudo` を使える WSL のユーザー、社内プロキシのアドレス `<社内プロキシのアドレス>`、社内 CA 証明書のファイル `<社内CA証明書のファイル名>`（入手方法: `<社内CA証明書の入手方法>`）

> この手順書にはパスワードを書きません。プロキシに認証がある場合は「付録 認証があるプロキシの場合」を見てください。

## 0. 今の状態を確かめる

```sh
echo "$PATH" | tr ':' '\n' | grep mybin
env | grep -i _proxy
```

確認: どちらも何も表示されなければ、まだ設定されていません。何か表示された場合は、その値をメモしてから進めます（「元に戻す方法」で使います）。

## 1. PATH に自分のコマンドの場所を足す

`~/mybin` に置いたコマンドを、名前だけで動かせるようにします。

### 1-1. .bashrc のコピーを取る

```sh
cp ~/.bashrc ~/.bashrc.bak
```

### 1-2. 置き場所を作り、試しのコマンドを置く

```sh
mkdir -p ~/mybin
printf '#!/bin/bash\necho "hello from mybin"\n' > ~/mybin/hello
chmod +x ~/mybin/hello
```

### 1-3. .bashrc に追記して反映する

`>>`（追記）を `>`（上書き）と打ち間違えないでください。単一引用符のまま打ちます。

```sh
echo 'export PATH="$HOME/mybin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

確認: `type hello` が `hello is /home/<ユーザー名>/mybin/hello` と表示し、`hello` で `hello from mybin` と表示されれば成功です。

## 2. apt でパッケージを入れる

社内ネットワークで `sudo apt update` が止まる場合は、`Ctrl+C` で止めて手順3の後にやり直します。

```sh
sudo apt update
sudo apt install -y tree
```

確認: `type tree` が `tree is /usr/bin/tree` と表示されれば成功です。

## 3. プロキシを設定する（社内ネットワークだけ）

### 3-1. シェルの環境変数

`<社内プロキシのアドレス>` を実際の値に置き換えてから実行します。

```sh
cat >> ~/.bashrc <<'EOF'

# --- 社内プロキシ（環境設定手順書で追加）---
export http_proxy="<社内プロキシのアドレス>" https_proxy="<社内プロキシのアドレス>"
export no_proxy="localhost,127.0.0.1"
export HTTP_PROXY="$http_proxy" HTTPS_PROXY="$https_proxy" NO_PROXY="$no_proxy"
# --- ここまで ---
EOF
source ~/.bashrc
```

- 小文字と大文字の両方を設定します。ツールによって読む名前が違うためです（curl は http の URL では小文字の `http_proxy` しか読みません）
- `no_proxy` の `localhost,127.0.0.1` は、自分の PC で動かすサーバへの通信をプロキシに送らないための設定です

確認: `env | grep -i _proxy` で、小文字と大文字の6行が表示されれば成功です。

### 3-2. apt

`sudo` で実行するコマンドには、3-1 の環境変数が引き継がれません。apt には専用の設定ファイルを置きます。

```sh
printf 'Acquire::http::Proxy "%s";\nAcquire::https::Proxy "%s";\n' "$http_proxy" "$http_proxy" \
  | sudo tee /etc/apt/apt.conf.d/95proxy
sudo apt update
```

確認: `apt-config dump | grep -i proxy` に `Acquire::http::Proxy` と `Acquire::https::Proxy` の2行が出て、`sudo apt update` がエラーなしで終われば成功です。

### 3-3. 社内 CA 証明書

```sh
head -1 <社内CA証明書のファイル名>
```

- `-----BEGIN CERTIFICATE-----` と表示されたら PEM 形式です。`cp <社内CA証明書のファイル名> company-ca.crt` で、拡張子 `.crt` の名前にします
- 文字化けした内容が表示されたら DER 形式です。先に変換します: `openssl x509 -inform der -in <社内CA証明書のファイル名> -out company-ca.crt`

```sh
sudo cp company-ca.crt /usr/local/share/ca-certificates/
sudo update-ca-certificates
```

確認: 出力の最後のほうに `1 added` と表示されれば成功です。

### 3-4. curl・git で確かめる

```sh
curl -v -o /dev/null https://example.com 2>&1 | grep -E 'Uses proxy|CONNECT|HTTP/'
git ls-remote https://github.com/git/git HEAD
```

確認: curl で次のような行が出て、git で40桁の英数字と `HEAD` が1行表示されれば成功です。

```console
* Uses proxy env variable https_proxy == '<社内プロキシのアドレス>'
> CONNECT example.com:443 HTTP/1.1
< HTTP/1.1 200 Connection established
```

## うまくいかないとき

`curl -v <URL>; echo $?` を実行し、表示と終了コードで止まった段階を見ます。

| 症状（表示・終了コード） | 止まった段階 | 確かめること・対処 |
| --- | --- | --- |
| `command not found` | PATH | `echo "$PATH" \| tr ':' '\n'`。`.bashrc` を壊したら `/usr/bin/cp ~/.bashrc.bak ~/.bashrc` |
| `Could not resolve host`（6） | 名前解決 | 社外の名前なら手順3-1 のプロキシの設定。`env \| grep -i _proxy` |
| `Could not connect to server`（7） | 接続（拒否） | 相手が動いているか、ポート番号。プロキシを設定しているなら、表示されたアドレスがプロキシのものか |
| `Connection timed out`（28） | 接続（返事なし） | 外に直接出ようとしている。手順3-1 の設定と、新しいターミナルで開いたか |
| `SSL certificate problem`（60） | TLS | 手順3-3。`0 added` なら拡張子が `.crt` か、PEM 形式か |
| curl は通るが `sudo apt update` が通らない | apt の設定 | `apt-config dump \| grep -i proxy`。手順3-2 |
| `apt update` で `esm.ubuntu.com` などの一部だけ失敗する | apt の設定 | `Acquire::https::Proxy` の行があるか |
| 自分の PC のサーバ（`127.0.0.1:8000`）にだけつながらない | プロキシ | `no_proxy` に `localhost,127.0.0.1` があるか |

## 元に戻す方法

```sh
cp ~/.bashrc.bak ~/.bashrc                                   # 手順1・3-1 を戻す
rm -r ~/mybin                                                # 手順1-2 を戻す
sudo apt remove -y tree                                      # 手順2 を戻す
sudo rm /etc/apt/apt.conf.d/95proxy                          # 手順3-2 を戻す
sudo rm /usr/local/share/ca-certificates/company-ca.crt
sudo update-ca-certificates --fresh                          # 手順3-3 を戻す
```

確認: 開いているターミナルを閉じ、新しいターミナルで手順0のコマンドを実行して、何も表示されなければ元に戻っています。

## 付録 認証があるプロキシの場合

（`<プロキシ認証の有無>` が「あり」の場合だけ）

パスワードを `.bashrc` やコマンドに直接書くと、ファイルやコマンド履歴（`~/.bash_history`）に残ります。ターミナルを開くたびに入力して、そのシェルの変数にだけ入れます。

```sh
read -rp "プロキシのユーザー名: " PROXY_USER
read -rsp "プロキシのパスワード: " PROXY_PASS; echo
export http_proxy="http://${PROXY_USER}:${PROXY_PASS}@<社内プロキシのホスト:ポート>"
export https_proxy="$http_proxy" HTTP_PROXY="$http_proxy" HTTPS_PROXY="$http_proxy"
```

- apt の設定ファイル（手順3-2）にはパスワードを書くことになるため、講師または情報システム部門に扱いを確認してください
- パスワードに `@` や `:` などの記号が入っている場合は、URL として正しく読めないことがあります
